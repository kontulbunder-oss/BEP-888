# BEP-888（项目提案代号）— Meme 纳斯达克指数与 dIDX 实物篮子 v1

2026-09-19。BEP-888 是 MemeDAQ 使用的项目协议名称与提案代号。BNB Chain 官方提交记录、受理状态及正式编号尚待核验。本文描述本仓库的实现；部署地址、初始化与储备余额由网站「dIDX 篮子」页直接核验链上状态。

## 定位与实用性

Meme 纳斯达克指数｜让 Meme 可以组合持有。四币实物储备、BNB 一键铸造、份额按比例赎回，建设同题材社区共同参与的入口。

当同题材出现多个 Meme 时，参与入口与社区关注容易分散。篮子让用户用一份份额同时持有所选成分的比例权益，减少分别购买、管理与反复换仓的操作，为不同社区提供联合展示与参与的工具。“实物储备”指真实持有的链上成分代币。

产品的组合方式是：链上真实储备与比例份额、一笔 BNB 购买并铸造、按比例赎回、使用篮子份额为新 Meme 主池计价。这些机制共同构成 MemeDAQ 的产品方案，不宣称首次发明可赎回篮子。

BROCCOLIIDX 是后续同题材扩展示例：将选定的多个 Broccoli 代币存入独立篮子，让用户组合持有。原有代币与外部交易池仍各自存在；组合不代表合并这些交易池或消除分流。当前尚未开放任意地址建篮功能，普通 Meme 使用该名称也不产生储备赎回权。

## 当前四币与后续 N 币方向

当前每个篮子固定四种成分，候选登记为四个 Meme 加待接入的 $MDAQ。$MDAQ 接入且新篮子具备真实储备与完整路径后，可逐步启用五选四组合。更多候选、更多主题与 N 币篮子属于后续扩展方向，需要新的合约实现与登记机制，现有四币篮子的成分与份额不会因文案或页面选择而改变。

## 五选四储备组合

候选为上面四个 meme 加平台币 $MDAQ。每次选择四个，共五种组合。原四币篮子保留原地址及全部份额；含平台币的四个组合分别部署自己的 `DidxBasket`、Gateway 和净值源。不同组合的 dIDX 是不同 ERC-20 合约，余额、储备、铸造、赎回、交易池和分红分别核算；页面切换选择不会兑换已有持仓。

`DidxBasketRegistry` 将初始四个候选固定，并允许发射台所有者一次性绑定第五个候选。登记新篮子时检查相同实现代码、四个不同候选、已初始化的非零储备，以及没有登记过的组合；不能替换已经登记的篮子。多组合发射台只接受一个已登记、已启用的篮子作为主池计价币。多组合回购合约按份额合约选择对应 Gateway，授权仅覆盖本笔数量并在结束后归零。

导出时生产配置尚无 $MDAQ 合约地址。含 $MDAQ 的组合在代币、价格源、兑换路径和真实储备接入前保持不可操作。公开的五选四测试见 `test/DidxFiveChooseFour.t.sol`；测试代币不会作为生产平台币地址发布。默认四币篮子的地址与只读核对结果见 `deployments/bsc-mainnet.json`。

篮子固定四个成分地址，没有管理员、提款、升级、更换资产、外部策略或再平衡入口。初始化人只能在总供应量为零时初始化一次；总份额为 1 dIDX，锁定 `1e6` 个最小单位，其余交给初始储备提供者。按等额 BNB 购入的初始成分，扣除交易费后的美元权重不必恰好相等；此后权重随价格变化。

## 记账、铸造与转账税

设总份额为 S，每项内部储备为 R_i，实际余额为 A_i，可兑储备 B_i = min(R_i, A_i)。直接转入的未记账捐赠不提高铸造价格，也没有救援接口可以将其取走。实际余额亏损在下一次操作时按同一份额比例分摊。

四项存入必须一起执行。实际到账 d_i 通过余额增量测得，而不是按转账参数或美元预言机估值入账。

```text
新份额 m = min_i floor(d_i × S / B_i)
所需净入库量 required_i = ceil(m × B_i / S)
```

`deposit` 检查最少份额、逐项超额存入比例、收款地址与截止时间，再发行份额。直接存入时，超额存入进入储备，由全体份额共同持有；用户指定的 `maxSurplusBps` 不得超过 1000（10%），网站的折叠直接存入入口使用 300（3%）。公开的 BNB 一键铸造入口只存入所需比例并使用零超额容忍，其余成分币原样退款。任何可兑储备为零时禁止存入。

`previewMint(m)` 返回每项所需净到账；成分如收取转账税，用户需要补足毛额或接受少于目标的份额，但始终受最少份额约束。

## 赎回

```text
每项毛输出 out_i = floor(s × B_i / S)
```

`redeem` 只销毁调用者自己的份额，按每项实际净到账检查 `minAmounts`。转账扣税由该次赎回承担；额外扣减篮子余额的异常转账被拒绝。份额与全部资产转账原子执行，失败则整笔回滚。

实物赎回不需要美元价格。一项余额归零时其输出为零，其他资产仍可按比例退出；一项非零资产冻结或拒绝转账时，整个退出可能失败。第一版没有跳过冻结资产、拆分债权或管理员紧急提款机制。

## Gateway

BNB 先包装为 WBNB，沿部署时固定并验证工厂归属的路径兑换：

- 龙虾：WBNB → 龙虾（V2）。
- 牛来：WBNB → USDT（V2）→ 牛来（V3）。
- 永生果蝇：WBNB → USDT（V2）→ AAPLB（V3）→ 永生果蝇（V2）。
- 哈基咪：WBNB → 哈基咪（V2）。

各段都要求输入全部消耗、实际净输出不低于对应限制；V3 部分成交会回滚。没有任意调用、任意审批目标或运行时替换路径。授权只给所需额度，操作后清零。本次交易仅使用本次包装或赎回所得的资产，不把旧余额分给后来用户。

网站的 `DidxRefundGateway.mintFromBnb` 在同一笔交易中购齐资产、按比例存入并铸造 dIDX，也可继续在指定 meme/dIDX 池买入 meme。无需预先持有或授权成分币，未花费 BNB 与未用于铸造的成分币退回付款钱包；成分币不再次换币。原 Gateway 保留供现有金库、回购及赎回使用。`redeemToBnb` 先按比例赎回，再逆向兑换，检查每段限制与最终 BNB 最低到账。网站分别提供篮子铸造和代币交易；卖出 meme 获得 dIDX 后可进入篮子页赎回。调用参数见 [BNB 铸造接口](didx-bnb-mint.md)。

## 净值、发射与维护

`DidxNavFeed` 读取各成分经过流动性、偏离和新鲜度检查的价格源，用实际可兑储备和总份额计算 USD/dIDX。V2 使用累计价格的 30 分钟观察，观察最长有效期两小时；V3 使用 30 分钟 TWAP。净值用于新 meme 的起始价格换算和显示，不决定核心铸造/赎回份额。

网站的展示层优先读取同一区块的实际储备与 V2 / V3 现货价格，显示每份 dIDX 的美元参考净值。首页参考指数也按现货计算，沿用指数合约的基准点位、成分、基准价与权重，每 15 秒刷新并标明读取时间；它与链上 30 分钟均价指数分别标注，不替代发射或交易的链上价格校验。现货读取失败时，如均价仍有效则明确显示均价来源；两种来源均失败时标记暂停更新，不把旧价格标成最新。

兑换操作区显示每份 dIDX 的美元和 BNB 参考值、输入数量的参考价值、预览到账金额及本次兑换价。BNB 美元价复用储备估值路径中通过链上新鲜度检查的 WBNB 价格源。当前储备估值与本次交易模拟报价用途不同，实际最低到账仍由原有报价与滑点限制决定。

任何人可调用 `updatePrices()` 维护观察。长期无人维护后，需重新积累窗口，新发射暂时停止；既有池交易、dIDX 存入与实物赎回仍不依赖这些预言机。单币兑换则始终依赖 DEX 的实际流动性。部署不意味着已建立永久付费维护服务。

新发射基础起始 FDV 为 6000 美元，按当前 NAV 换算 dIDX 价格。`launchBasket` 强制单个 dIDX 池，全部初始 meme 单边加入并永久锁定。第一版该入口不包含创建者 BNB 首买；发射后在代币页买入。

## 税费、分红与平台币

主池沿用原 Hook 的基础 1% 交易税：创建者 0.2%、持有者 0.5%、回购 0.3%，均以 dIDX 结算。启动阶段另有递减的防抢跑税，实际税率以链上 Hook 为准。原有快照与排除池库存的分红机制继续适用。

回购合约可以收集 dIDX，通过固定 Gateway、净值下限和逐段限制赎回成 BNB。后续购买销毁 $MDAQ 仍需要平台币真实发行和绑定；dIDX 部署不表示 $MDAQ 已发行。

篮子本身无管理员提款。发射台仍有原有管理员配置权：未来发射价格、计价币配置、买入暂停、回购地址一次性绑定等；回购仍使用所有者/keeper 权限。不能把篮子的无管理权限推广成整个协议都没有管理权限。

## 验证与风险

实现配套有不同精度、转账税、最小到账、捐赠操纵、余额损失、冻结回滚、取整和往返不增益测试。公开测试与本次执行结果见 `test/` 和 `docs/VALIDATION.md`；本次导出不包含依赖私有运维配置的历史分叉演练脚本。测试和源码匹配不是独立审计。

共同篮子也有共同风险：任何成分下跌、冻结、发行方权限、交易深度不足或合约漏洞都可能影响全部 dIDX 持有者与使用它的 meme 市场。单一主池不消除 MEV、外部建池或投机价格波动，也不承诺收益。
