## 摘要

MemeDAQ 是 BNB Chain 上的 Meme 发射台与组合持有协议，用户可创建使用登记 dIDX 主池的新 Meme。其储备层定义并实现由多种链上成分资产支持的可赎回份额，以及将 BNB 兑换、比例存入、份额发行与剩余资产退款合为一笔交易的入口。参考实现 dIDX 固定四项资产，支持按当前可兑储备比例赎回，并可作为 Meme 交易池的计价资产。

## 动机

同题材的多个 Meme 可能分散参与入口。用户若希望组合参与，需要分别买入和管理资产，再在退出时逐项操作。本提案为用户提供一份组合权益和 BNB 原子入口，为社区提供共同展示与参与的产品基础。它不自动合并原有代币或交易池，不声称消除分流或证明社区协作效果。

## 定义与范围

- **成分币**：篮子真实持有的链上代币，地址固定于篮子构造时。
- **份额**：ERC-20 形式的比例权益；份额数量不是固定美元承诺。
- **当前可兑储备**：每项内部记账储备与实际余额的较小者。
- **BNB 入口**：仅沿部署时配置的 V2/V3 路径购买成分，检查逐段最低到账。
- **当前版本**：所有资产数组固定长度四。N 资产规范、任意主题和无许可建篮不在当前实现范围内。

## 规范

设总份额为 `S`，内部记账储备为 `R_i`，实际余额为 `A_i`，当前可兑储备为 `B_i = min(R_i, A_i)`。所有数量使用代币最小单位，所有比例运算按明示方向取整。

### 初始化

构造时固定四个不同合约地址和一次性初始化地址。初始化要求四项实际净到账均至少 `1e6` 个最小单位。初始发行 `1e18` 份额最小单位，其中 `1e6` 永久锁定，其余交给初始化指定接收人。默认份额精度 18；这不表示每份固定价值 1 美元。

### 存入和发行

四项输入必须一起执行。实际到账 `d_i` 由转账前后余额差得到：

```text
m = min_i floor(d_i × S / B_i)
required_i = ceil(m × B_i / S)
```

发行 `m` 必须达到用户指定 `minShares`。每项超额到账必须符合 `maxSurplusBps`（合约上限 1000）。直接存入时，用户接受的超额留在篮子；公开 BNB 退款入口仅存入所需比例，使用零超额容忍，剩余成分原币退款。任何一项可兑储备为零时不允许新增存入。

### BNB 一笔进入

1. 用户指定四项 BNB 预算、每段最低到账、最低份额、接收人和截止时间，附带 BNB。
2. 固定路径购买成分；本次所得与历史残留余额分开计算。
3. 由实际买到的数量和当前储备比例计算可铸份额。
4. 按向上取整的所需数量授权并存入篮子，铸造份额。
5. 将份额交给接收人；可选继续调用已配置 Meme 路由买入指定 Meme。
6. 清零临时授权，多余成分币和未使用 BNB 退给付款人 `msg.sender`。

接收人可以不同于付款人。失败、过期、最低到账不足、比例不符或退款失败都会回滚整笔交易。对于向篮子转账再扣税、使精确比例存入失败的资产，公开退款入口会原子回滚；直接存入入口对转账税另按净到账规则计算。不能将两种入口的资产兼容范围混为一谈。

### 按份额赎回

```text
out_i = floor(shares × B_i / S)
```

只销毁调用者自己的份额。每项最低到账检查收款人的实际净增加量；单次成分转账税由该次赎回承担。额外扣减篮子发送余额的异常行为被拒绝。核心实物赎回不依赖美元预言机；兑换 BNB 还依赖各路径流动性与最低到账限制。

### 记账与权限

未记账捐赠不提高内部可兑储备，也没有管理员提款入口。实际余额低于账面时按实际余额分摊；一个非零成分拒绝转账可令整笔退出失败。当前篮子没有跳过冻结成分、管理员紧急提款、替换成分、再平衡或升级功能。

登记表、发射台和回购模块拥有各自的管理权限；篮子的不可管理属性不能推广为整套协议无管理权限。详见[权限边界](../docs/PERMISSIONS.md)。

### 指数、净值与报价

净值为当前可兑储备美元总价值除以总份额。参考指数根据成分相对基准价的表现和基准权重计算。两者不等同。

前端现货估值只用于展示；新 Meme 的起始定价使用链上有效均价源。核心存入/实物赎回依赖实际资产比例，单币兑换依赖实际交易模拟。报价必须设置截止时间、逐段最低到账和最终最低份额/金额。

## 接口

完整接口见[BNB 入口说明](../docs/didx-bnb-mint.md)及 Solidity 源码。

```solidity
function assets() external view returns (address[4] memory);
function reserves() external view returns (uint256[4] memory);
function previewMint(uint256 shares) external view returns (uint256[4] memory);
function previewRedeem(uint256 shares) external view returns (uint256[4] memory);
function deposit(uint256[4] calldata amounts, uint256 minShares, uint16 maxSurplusBps,
    address receiver, uint256 deadline) external returns (uint256 shares);
function redeem(uint256 shares, uint256[4] calldata minAmounts,
    address receiver, uint256 deadline) external returns (uint256[4] memory received);
```

## 设计理由与兼容性

选择固定四项让 v1 的路径和成分边界明确。采用当前储备数量比例，避免把美元价格操纵引入核心份额发行和实物赎回；美元显示和单币路由仍各有依赖。原币退款减少一次不必要的再次兑换。份额符合基础 ERC-20 接口，不宣称兼容单资产 ERC-4626。

不同组合是不同 ERC-20 合约，不可混用余额、授权和赎回参数。现有篮子不可升级，未来 N 项方案需新实现；用户迁移权益必须独立设计，不能依靠页面切换隐式完成。
